# Parent — API còn thiếu và contract cần bổ sung (source audit 01/11/2026)

> **Đọc truyện cập nhật 05/11:** FE đã nối `GET /api/story-template/stories/{id}` và `GET /api/storypage-template/pages/{storyId}`; reader Parent có phân trang và audio. Endpoint trang được lọc Active phía FE vì source tham chiếu có thể trả status khác Active. Cần BE xác nhận quyền gói và phạm vi dữ liệu trên deploy. Xem [kế hoạch Reader Parent 05/11](PARENT_READER_INTEGRATION_PLAN_2026-11-05.md).

> **Payment cập nhật 04/11 — ưu tiên hơn trạng thái payment cũ bên dưới:** đã xác nhận trên Swagger live ba route `POST /api/payments/create-checkout`, `POST /api/payments/webhook`, `PATCH /api/payments/cancel-paymentlink`; đối chiếu source remote `9927acf`. Frontend chưa nối; thiếu API tra cứu giao dịch/lịch sử Parent được expose và còn điểm cần hoàn thiện trong kích hoạt quyền lợi/hủy PayOS. Xem [kế hoạch nối Payment 04/11](PARENT_PAYMENT_INTEGRATION_PLAN_2026-11-04.md). Không đánh đồng source local cũ với source remote mới.

> **Rà soát lại ngày 01/11:** dùng [plan hiện hành](PARENT_INTEGRATION_PLAN_2026-11-01.md) và [câu hỏi chuyển Backend](PARENT_BACKEND_QUESTIONS_2026-11-01.md). Development đang bật catalog real, profile/approvals vẫn mock; production cả ba module mock. Inbox approval đã có local source + FE live view. ParentProfileDto đã có RemainingChildProfile/RemainingMonthlyCredit: xác minh response auth/profile và semantics/reset trước khi đề xuất API quota mới. Các endpoint đề xuất bên dưới là backlog; không phải tất cả đều chặn core MVP.

Đối chiếu các snapshot Swagger (124 operations), frontend hiện tại và backend source baseline [`fb3075e`](https://github.com/iamhyyyy/sketch-tale-backend/tree/fb3075e33d584abbb185fcc860aeec206f8af9a0). Các sửa đổi Backend sau baseline nằm trong working tree local; route mới chưa được phản ánh trong Swagger live/snapshot cho tới khi build và phát hành. Chi tiết source/controller/service: [Parent source audit 01/11](PARENT_API_SOURCE_AUDIT_2026-11-01.md); thứ tự nối tối ưu: [Parent integration plan 01/11](PARENT_INTEGRATION_PLAN_2026-11-01.md). Chưa xác nhận source mới đang chạy trên Render; chưa có authenticated live test. Kế hoạch ngày 29/10 là lịch sử; dùng [API integration master](API_INTEGRATION_MASTER_2026-11-01.md) cho quy trình hiện hành.

Các URL ở mục 2 là **đề xuất**, không phải API đã có. Có thể mở rộng API hiện hữu thay vì tạo endpoint mới. Không dùng số endpoint đề xuất làm tỷ lệ hoàn thành sản phẩm. Đây là bản phân loại mới; danh sách 26 endpoint ngày 21/10 trong `docs/PARENT_MISSING_APIS_BACKEND.md` là tài liệu lịch sử và chi tiết tham khảo.

| Đổi mật khẩu | `POST /api/auth/change-password` | **Backend code và FE caller dùng chung có** ở trang hồ sơ tài khoản. Không phải API còn thiếu riêng của Parent. |
| Upload avatar | `POST /api/upload/avatar` | **Backend operation có nhưng chưa thấy FE caller** trong source. Upload thành công chưa chứng minh ảnh đã gắn vào Parent/ChildProfile; cần luồng lưu URL/profile association nếu bật sửa avatar. |

**Phê duyệt nhân vật — Backend và FE có inbox/decision flow trong local source:** mapping API đã scope theo owner và transition Pending → Approved/Rejected. Local Backend bổ sung `GET /api/user-story-character-mappings/child/{childProfileId}` trả trang, tên nhân vật, ảnh, truyện, vai, trạng thái và thời gian; Parent FE có inbox live adapter/UI và `PATCH /api/user-story-character-mappings/{id}`. Mặc định Parent approvals vẫn mock; chỉ bật `VITE_PARENT_APPROVALS_API_MODE=real` sau khi source mới build/deploy và kiểm tra trên staging. Contract hiện chưa có revision, lý do từ chối hoặc quyền vai nhạy cảm.

**`/api/users` — API Admin đã có, không phải Parent self-service:** các operation list/detail/create/update/status được code và có caller trong Admin service. Update dùng `AdminUpdateUserDto`, có field `role`; Backend source gắn quyền Admin cho controller này. Parent không có caller và không nên dùng endpoint Admin để sửa hồ sơ tài khoản của mình.

## 3. Backend fix cần thiết và điểm chỉ runtime mới kết luận được

1. **P0 — Ownership (đã sửa trong Backend local, runtime chưa xác minh):** ChildProfile list/detail/update lấy Parent từ JWT; Child scope tự thân. ParentProfile và Subscription CRUD vẫn không owner-scoped, nên Parent không được dùng các route đó. Chỉ bật profile mode sau build/deploy và test Parent A/B trên staging.
2. **P0 — Story visibility (đã sửa trong Backend local, runtime chưa xác minh):** list/by-theme/detail Parent/Child lọc `Active`; FE còn fail-closed nếu trạng thái lạ. Production catalog giữ mock cho tới khi Backend mới được phát hành và không lộ Draft/Pending/Archived được xác minh.
3. **Register/refetch:** `/auth/profile` vẫn không trả ChildProfiles; Backend local đã bổ sung `childProfileId` vào response register và ChildProfile list được scope. Kiểm tra read-after-write sau deploy.
4. **Approval mapping (security + inbox local, release pending):** owner checks, resource relationship checks, status whitelist/transition, parent-scoped inbox and Parent FE live list/decision are implemented in local Backend/Frontend source. Production mode remains mock by default; build/deploy/staging A/B owner validation is still required. Revision, reject reason, sensitive-role grant and runtime behavior remain unsupported.
5. **P1 — Story pages (đã có route trong Backend local):** `/storypage-template/published/{storyId}` cho Parent/Child, chỉ trả pages Active của story Active; chờ build/deploy/live verification.
6. **P1 — Plan:** định nghĩa `haveParentProfileSub`, `SubscriptionStatus` và hiệu lực thời gian. DTO không có currency; frontend dùng VND theo cấu hình hiện hành. Nếu hỗ trợ nhiều tiền tệ, Backend cần trả currency rõ ràng. Không suy field mới thành “đang đăng ký”, quyền mua gói hoặc usage thực tế.
7. **P1 — API lỗi:** thống nhất envelope/validation, 401/403/404/409/429, pagination; không tự giả định tất cả endpoint trả cùng wrapper.

**Trạng thái runtime:** `fb3075e` là baseline trước các sửa đổi local; chưa xác nhận Backend local đã build/deploy lên Render. Các sửa đổi source không chứng minh response thật; production profile/catalog vẫn mock. Không gọi các API unscoped để thử bằng tài khoản thật.

## 4. Tiêu chí bàn giao Backend → Frontend

- Swagger có request/response schema và enum nghĩa rõ; examples success/empty/validation/forbidden/conflict.
- Có test data Parent A/B và Child thuộc từng Parent để kiểm chứng quyền; không ghi credential vào repo.
- Read-after-write trả dữ liệu đã lưu; cache tách User ID, ChildProfile ID và nguồn real/demo.
- Mutation lặp không tạo thanh toán/export/quyết định trùng. Xử lý revision cũ nếu nghiệp vụ có concurrent update.
- Frontend chỉ thay phần demo tương ứng khi contract sẵn sàng; API thật lỗi không chuyển sang dữ liệu demo.
- Bản rà soát này là phân tích Swagger/source; chưa thực hiện test authenticated live hoặc mutation backend.
